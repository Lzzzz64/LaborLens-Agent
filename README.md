# LaborLens

一个面向中国大陆劳动者的劳动合同与用工经历智能分析 Demo。

LaborLens 通过文档解析、事实结构化、动态追问、法律资料检索和规则校验，帮助用户理解劳动合同中的关键约定、事实缺口和潜在风险。项目重点不是替代律师，而是探索如何构建一个结论有边界、引用可追溯、失败可解释的大模型应用。

> 当前状态：需求与实施计划已经完成，功能代码尚在开发中。

## 项目目标

LaborLens 是一个大模型应用工程作品集项目，主要验证以下能力：

- 将 PDF、合同图片和自然语言经历转换为结构化案件事实。
- 根据事实缺口动态选择问题，而不是使用固定问卷。
- 组合国家、浙江省和杭州市的公开法律资料进行检索。
- 让确定性规则与大模型各自处理适合的问题。
- 对法律引用、事实依据和结论强度进行约束。
- 使用固定测试集重复评测风险识别、引用质量和幻觉情况。
- 完整交付前端、后端、数据存储、容器编排和自动化测试。

## 核心流程

```text
PDF 图片 经历描述
        │
        ▼
文档解析与 OCR
        │
        ▼
事实结构化与置信度标记
        │
        ▼
紧急事项筛查
        │
        ▼
动态追问 最多三轮
        │
        ▼
关键词与向量混合检索
        │
        ▼
规则判断与模型分析
        │
        ▼
引用校验与结论降级
        │
        ▼
网页报告与 PDF 导出
```

用户可以从两个入口创建案件：

1. **合同审查**：上传文本型 PDF、扫描 PDF 或合同图片。
2. **经历分析**：描述试用期解除、欠薪、调岗降薪、离职补偿等用工经历。

两个入口最终进入同一个案件工作区，共用事实、问答、检索、风险和报告状态。

## 主要功能

### 输入与事实提取

- 支持文本型 PDF、扫描 PDF 和常见图片格式。
- 支持直接输入工作经历和希望达到的目标。
- 抽取主体、地点、日期、合同约定、企业行为、用户诉求和已有证据。
- 对 OCR 识别出的金额、日期和否定词保留置信度。
- 明确区分已知事实、用户主张、模型推断和未知信息。

### 动态追问

- 在分析前识别可能改变结论的事实缺口。
- 每轮最多提出三个问题，总轮数不超过三轮。
- 优先询问对判断影响最大或具有时效性的内容。
- 用户可以跳过问题；系统随后输出有限结论并列出缺口。

### 法律资料检索

- 使用关键词和向量进行混合召回与重排。
- 保存查询、候选结果、排序过程和最终采用来源。
- 按地域、时间和有效状态过滤资料。
- 引用可定位到具体法规、条文、政策或案例记录。
- 非官方文章只能作为人工收集线索，不能作为报告最终依据。

### 风险分析

- 规则引擎处理期限、比例和必备项等确定性问题。
- 大模型处理复杂事实理解、条件分析和解释。
- 报告明确标记规则判断与模型判断。
- 无有效依据时不生成确定性法律结论。
- 模型与规则冲突、来源状态不明或事实不足时降级为“待核实”。

### 分析报告

报告采用固定结构，主要包含：

1. 一句话结论。
2. 当前最优先处理的三件事。
3. 事实摘要和待确认信息。
4. 完整风险清单和风险等级。
5. 每项风险的法律依据、适用理由、判断类型和置信度。
6. 已有证据、证据缺口和补充建议。
7. 结合用户目标的行动步骤和沟通话术。
8. 系统能力边界和需要寻求专业帮助的情形。

## 可靠性设计

法律场景无法只依赖模型生成质量。LaborLens 将可靠性控制放入主流程，而不是作为开发完成后的附加功能。

### 可追溯结论

每项法律判断都应至少关联以下一种依据：

- 确定性规则及其版本。
- 本次检索轨迹中的法律来源。
- 支持判断的具体来源片段。

模型只能引用本次检索结果中的来源标识。引用不存在、已经失效或不能支持结论时，系统会阻止输出或降低结论强度。

### 失败降级

- OCR、模型和检索调用采用有界重试与超时控制。
- 外部依赖持续失败时保留案件和用户输入。
- 失败状态会明确展示，不生成看似完整的伪分析结果。
- 紧急提醒不会被普通报告内容覆盖。

### 隐私处理

- 演示和自动化测试默认使用虚构材料。
- 用户上传的原始文件只保存在临时目录。
- 文件在解析成功、失败终止或超时清理后删除。
- 原始合同文件不写入 MySQL。

## 风险等级

| 等级 | 适用情况 | 系统行为 |
|---|---|---|
| 高 | 可能涉及紧急时效、重大损失或立即签字风险 | 置顶提醒，说明依据和未知项，建议尽快寻求专业帮助 |
| 中 | 存在较明确的不利条款或争议，需要补证或沟通 | 提供证据缺口、沟通步骤和条件化结论 |
| 低 | 条款值得关注，但当前事实不足以显示明显损害 | 解释含义并提示后续观察事项 |
| 待核实 | 缺少关键事实、来源状态不明或规则与模型冲突 | 不输出确定结论，列出核实清单 |

## 计划技术架构

| 组件 | 技术 | 职责 |
|---|---|---|
| 前端 | React、TypeScript | 案件创建、文件上传、动态问答、进度与报告展示 |
| 后端 | FastAPI | 接口、业务编排、解析、检索、规则和报告生成 |
| 工作流 | LangGraph | 显式管理节点、条件分支和案件状态 |
| 业务数据库 | MySQL | 保存案件、事实、问答、风险、引用和评测记录 |
| 向量数据库 | Chroma | 保存法律资料向量、元数据和知识库版本 |
| 模型 | OpenAI 兼容接口 | 通过统一适配层调用可配置模型 |
| 部署 | Docker Compose | 统一编排前端、后端、MySQL 和 Chroma |

计划中的 LangGraph 工作流使用单一状态机，而不是多个模型角色相互讨论。主要节点包括：

```text
输入接收
  → 内容解析
  → 事实结构化
  → 紧急筛查
  → 缺口分析
  → 动态追问
  → 法律检索
  → 风险判断
  → 引用校验
  → 报告生成
```

## 评测方案

项目计划建设包含 20 至 30 个虚构标注案例的固定测试集，覆盖：

- 无明显违法风险的正常合同。
- 法律适用存在条件的边界合同。
- 包含明显缺失项、不利条款或紧急签字情形的高风险合同。
- 试用期解除、欠薪、调岗降薪和离职补偿等经历案例。
- 错误日期、冲突陈述、OCR 易错字符和诱导模型编造依据的对抗样本。

计划评测指标：

| 指标 | 关注的问题 |
|---|---|
| 风险识别召回率 | 是否遗漏关键风险 |
| 风险识别准确率 | 是否产生过多误报 |
| 引用正确率 | 来源是否真实、有效并支持结论 |
| 幻觉率 | 是否编造法条、事实或无依据的确定结论 |
| 追问完整率 | 是否覆盖会改变结论的关键缺口 |
| 结构化输出成功率 | 输出是否稳定通过数据模型校验 |
| 端到端成功率 | 核心流程能否在无人工干预下完成 |

评测运行将记录数据集、知识库、模型配置、提示词和规则版本，并保留失败样本供复盘。

## 能力边界

LaborLens 是技术演示项目，不提供律师服务，也不建立任何代理关系。第一版明确不包含：

- 对案件结果作出保证。
- 生成仲裁申请书、起诉状等正式程序文书。
- 解析录音、聊天记录、银行流水或复杂证据包。
- 覆盖全国所有地方政策。
- 自动联系企业、律师或政府部门。
- 真实账户、支付、获客、运营后台等商业功能。
- 多 Agent 协作或独立审查 Agent。

如果问题涉及紧急时效、重大损失、立即签字或复杂争议，用户应及时向合格的法律专业人士求助。
